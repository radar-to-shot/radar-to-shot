# Submit a robot

Copy [the robot template](../templates/robot.bot) to
`robots/<author-id>/<robot-id>.bot`, replace its identity header, and edit the
program. The template contains the small, working Compass Scout starter from
the [language reference](../web/docs/language.md). Test against several opponents
and seeds, then submit a pull request with your robot text file.

```text
; @author: Ada Example
; @author-id: ada-example
; @name: Compass Scout
; @robot-id: compass-scout
; @version: 1.0.0

; Robot program follows here.
```

The first three identifying values—**author, robot name, and version**—are required
whenever a metadata header is present. `author-id` and `robot-id` are optional,
but include them as in the template to keep history stable when a display name
or filename changes. Metadata is ordinary semicolon-comment text and does not
change the program executed by the original compiler or the headless engine.

| Field | Purpose | Rules |
| --- | --- | --- |
| `@author` | Author display name in standings | 1–64 printable characters |
| `@author-id` | Stable author history key | 1–48 ASCII letters/digits, with single hyphens between words; case is normalized to lowercase |
| `@name` | Robot display name in standings | 1–64 printable characters |
| `@robot-id` | Stable robot key within its author | Same slug rules as `author-id`; do not include the author prefix |
| `@version` | Version displayed beside the robot | 1–32 letters/digits or `.`, `_`, `+`, `-`, beginning with a letter or digit |

Use a version such as `1.0.0`, `1.1.0`, or `2.0.0`. The league treats it as a
label rather than guessing which version is newest from filenames or version
sorting. Increase it when changing behavior. Historical submissions without a
known version may explicitly use `unversioned`.

All `; @...` comments are reserved for these fields and belong before the first
program statement. Blank lines and ordinary comments may appear among them.
Unknown field names, duplicates, malformed lines, partial headers, and metadata
placed after executable statements are errors. This catches misspelled identity
fields instead of silently starting a new history record.

When IDs are omitted, the league derives them from the author and robot names
by removing accents and joining ASCII words with hyphens. Some names cannot form
such a slug, and different names can derive the same slug; supply explicit IDs
in those cases. Explicit IDs are the recommended way to preserve identity.

## Updating a robot or author

- Keep `author-id` unchanged across your submissions and display-name changes.
- Keep `robot-id` unchanged across a robot's renamed files, revised strategy,
  and version updates. Its full history key is `author-id/robot-id`.
- Change `robot-id` when submitting a separate competing robot. Two authors can
  use the same robot slug because each author's namespace is separate.
- Keep one active source file for each full robot identity. Replace the previous
  file when updating a version; keep older versions in Git history rather than
  entering several versions of the same robot simultaneously. All conflicting
  files are unranked if more than one claims that identity.
- Use the same author display name across all submissions with your author ID in
  a given week. A future rename is supported, but conflicting current names for
  one author ID make those entries unranked until the names agree.
- Do not reuse another contributor's author ID. Attribution is supplied by the
  submission and reviewed in the pull request; the header is not an authentication
  or identity-verification mechanism.

The weekly league recomputes ratings from the current programs. History connects
those weekly observations and display-name/version changes; it does not carry
old ratings into the next week's fresh fit. See [the weekly league documentation](WEEKLY_LEAGUE.md)
for the author standings and historical scoring rules.

## Older scripts and existing examples

Scripts without metadata remain eligible. Their filename supplies the display
name, their version is `unversioned`, and their author is **Unattributed**.
Unattributed files retain path-based legacy identities; they are not silently
credited to a Git committer, directory owner, or guessed author. Add a complete
header to attribute them. An unattributed script's old path identity cannot
establish ownership of a newly declared author identity.

The bundled model benchmark scripts have headers based on their existing
“Generated by” comments. Robot names are taken from existing program comments
where available; otherwise their existing filename stem is retained. Versions
remain `unversioned` unless the script already states a version. The standard
sample robots retain their original source files and unattributed status.

## Encoding and testing

Save submissions as UTF-8 text with a final newline. The file runners convert the
entire source—including comment headers—to the original **Mac Roman** character
set and normalize line endings. All characters must be representable in Mac
Roman, and the normalized file must fit within **32,767 bytes**. Plain ASCII
identities and code are the most portable choice. To run a file already encoded
in Mac Roman, use the runner's `--encoding mac-roman` option.

Compile and battle in [Robot Warriors Lab](https://radar-to-shot.github.io/radar-to-shot/),
or use the native runner:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
python scripts/run_headless_battle.py \
  robots/ada-example/compass-scout.bot robots/examples/Seeker \
  --seed 42 --ticks 2000 --output build/battle.json
```

The [language reference](../web/docs/language.md) and [agent brief](../web/docs/agent-brief.txt)
describe attributes, instructions, registers, timing, sensors, weapons, and
compatibility quirks. The source path is still recorded in league JSON for
replay even when the public leaderboard shows the friendly name and author.
